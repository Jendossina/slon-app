# Android-приложение (APK)

Приложение для Android — это **оболочка вокруг сайта**. Внутри тот же код, что и
в браузере: оболочка открывает `https://slon-app.vercel.app` (адрес задан в
`capacitor.config.json`).

Что это даёт:

- иконка на главном экране ставится **файлом**, мимо браузера и Play Маркета —
  работает на любом Android, включая телефоны без сервисов Google;
- открывается без адресной строки, своей иконкой, как обычное приложение;
- **обычные правки кода доезжают до сотрудников сами**, как сейчас. Пересобирать
  APK при каждом изменении не нужно.

Пересборка нужна, только когда меняется сама оболочка: иконка, разрешения,
название или адрес сайта.

## Первая настройка (один раз)

### 1. Создать ключ подписи

Ключом подписывается каждая сборка. Android ставит обновление поверх старой
версии, **только если оно подписано тем же ключом**, поэтому ключ нельзя терять:
без него обновить установленное приложение будет невозможно, придётся просить
всех удалить старое и поставить заново.

В репозиторий ключ не кладём. Создай его у себя:

```
"C:\Program Files\Java\jre-1.8\bin\keytool.exe" -genkeypair -v ^
  -keystore slon-release.jks -keyalg RSA -keysize 2048 -validity 10000 ^
  -alias slon -dname "CN=Slon Shisha and Bar, OU=IT, O=Slon, L=Tashkent, C=UZ"
```

Он спросит пароль — придумай и **сохрани в менеджере паролей**. На вопрос про
пароль ключа можно нажать Enter, тогда он совпадёт с паролем хранилища.

Дальше переведи файл в текст, чтобы положить его в секреты:

```
certutil -encode slon-release.jks slon-release.b64
```

Из полученного файла нужна вся середина — без строк `-----BEGIN...` и `-----END...`,
одной строкой без переносов.

### 2. Добавить секреты в GitHub

Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**.
Четыре штуки:

| Имя | Что положить |
|---|---|
| `SLON_KEYSTORE_BASE64` | содержимое `slon-release.b64` без строк BEGIN/END |
| `SLON_KEYSTORE_PASSWORD` | пароль, который придумал |
| `SLON_KEY_ALIAS` | `slon` |
| `SLON_KEY_PASSWORD` | тот же пароль (или отдельный, если задавал) |

## Сборка

Вкладка **Actions** → **Android APK** → **Run workflow**. Через несколько минут
файл появится в разделе **Releases**.

Номер сборки (`versionCode`) берётся из номера запуска и растёт сам — значит,
следующая сборка нормально встанет поверх предыдущей.

## Как ставят сотрудники

1. Открывают ссылку на APK из релиза (можно кинуть в чат персонала).
2. Скачивают файл и нажимают на него.
3. Android один раз спросит разрешение ставить приложения из этого источника —
   надо согласиться. Дальше обычная установка.
4. На экране появляется иконка «Slon».

## Что внутри оболочки

- `capacitor.config.json` — адрес сайта, имя и идентификатор приложения (`uz.slon.app`).
- `android/` — сгенерированный проект. Правился руками только в двух местах:
  - `AndroidManifest.xml` — разрешения на геолокацию (отметка прихода проверяет,
    что сотрудник на месте). Разрешение камеры намеренно **не** объявлено: фото и
    видео снимает системная камера по интенту, а если объявить `CAMERA`, Android
    начнёт требовать его и у нас, и съёмка сломается;
  - `app/build.gradle` — подпись из переменных окружения и номер версии из номера
    сборки.
- `www/` — заглушка «нет связи». Видна, только если сайт недоступен.

## Про iPhone

Для iOS такой способ не работает: Apple запрещает установку мимо App Store.
Айфоны продолжают пользоваться через Safari — там установка на главный экран
работает штатно.
